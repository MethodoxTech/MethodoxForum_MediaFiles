# MethodoxForum_MediaFiles

Publicly accessible media files for the Methodox Forum. The forum at `forum.methodox.io` serves them from its own `/m/<path>` route, fetched from this repository at a pinned tag, so a file's address on the forum is its path here.

## Layout

| Path | What it is |
|---|---|
| `badges/<key>.svg` | One per badge the forum awards: `first-post`, `posts-10`, `posts-100`, `posts-1000`, `solution-1`, `solution-10`, `solution-100`, `thanked-10`, `thanked-100`, `graph`, `bug-hunter`, `beta-tester`, `helper`, `package-author`, and the yearly `year-1` to `year-10`. Drawn to read at 22 pixels. |
| `ranks/<1-5>.svg` | The rank emblems in order: Fresh Node, Wire Runner, Graph Smith, Pipeline Architect, Divooka Sage. |
| `boards/<board id>.svg` | One icon per board, named by the board's number: 1 Announcements, 2 Help & Questions, 3 Graph Showcase, 4 Packages & Divooka Central, 5 Bug Reports, 6 Ideas & Feature Requests, 7 Methodox One & divooka.app, 8 The Lounge, 9 Getting started, 10 Data & tables. Each is the whole lamp tile in the board's colour, to be shown as it is. |
| `avatars/<nn>.svg` | The avatar gallery members can choose instead of uploading a photo, square portraits numbered from `01`. |
| `avatars/index.json` | The gallery in order: `{"avatars":[{"file":"01.svg","title":"Fox"},…]}`. |
| `brand/methodox-m.svg` | The Methodox M, the brand's mark, in the forum's ink on its own grid of 244 by 207, edge to edge, so whoever places it chooses its margins. |
| `brand/forum-logo.svg` | The forum header's 44-pixel logo: the brand M in white on the header's glass tile. |
| `manifest.json` | Every file above with its kind, key, title and size. |

The paths are a contract with the forum: a picture may be redrawn, but not moved or renumbered, and new portraits are added at the end of the gallery.

## How the files are made

Every file here is generated by ForumArt, a utility in the Parcel NExT repository (`Parcel.NExT/Utilities/ForumArt`), which draws each piece from code with `Divooka.Graphics.Canvas`, the M through the `Methodox.Branding` package's procedure for it, and writes it through that package's SVG writer. Nothing is drawn by hand and nothing is random, so do not edit the files: change the tool and run it again over a clone of this repository, from the root of Parcel NExT:

```
dotnet run --project Parcel.NExT/Utilities/ForumArt -- <this clone> [--preview <contact sheet.html>]
```

It rewrites only the files whose drawing changed, removes any SVG in `badges/`, `ranks/`, `boards/`, `avatars/` and `brand/` that it no longer draws, and writes `avatars/index.json` and `manifest.json`. It then reads every file back, draws it at the size the forum shows it, and exits with 3 if any is empty, cut off by its frame, or unsafe to serve. `--preview` writes a contact sheet showing every piece at those sizes on the forum's colours; keep it outside this repository, which holds only the art.

The SVGs carry no script, no style sheet and no reference to anything outside themselves, since the forum serves them under a policy that forbids all three. Each file names its gradients and clips after its own kind and key, so several can be set inline in one page without taking each other's.
